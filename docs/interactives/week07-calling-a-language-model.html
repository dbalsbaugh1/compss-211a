Calling a language model

Week 7 · Language model APIs About 10 minutes Simulated: nothing is sent, no key needed

Researchers often label texts by hand: they read each one and give it a category from a codebook. This is also called coding or annotation. A language model can do the same through an API. Here you label six comments yourself, see what one call to Gemini sends and gets back, and compare its labels with yours.

1·Label the comments yourself

The post:

A codebook lists the labels and says what each one means. Read it, then give each comment one label. Label them before you see the model's labels, so that its answers don't change yours.

2·What one call sends and gets back

In Python, you call Gemini with client.models.generate_content(...). The call sends the name of the model, a system instruction with the task and the codebook, a prompt with one comment, and settings. Here the settings are a schema, which lists the fields the answer must have and the labels it may use, and the temperature.

✓Remember

  

    
    
      
  • A codebook names the labels and defines each one. The model only knows what the system instruction tells it.
    • 
      
  • One call sends the model name, a system instruction, a prompt and settings. The answer comes back as text. With a schema, that text is JSON, and json.loads turns it into a dictionary.
    • 
      
  • The response also says how many tokens went in and came out. Services charge by the token.
    • 
      
  • Label a sample yourself before you trust the model. Read every disagreement: one of you misread the comment, or the definition does not cover it.
    • 
      
  • A change to one definition can change the labels. So can sending the same call again. Save the model name, the codebook version, the temperature and the date with every set of labels.
